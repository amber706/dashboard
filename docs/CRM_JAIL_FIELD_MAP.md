# CRM Jail — Scorecard Item → Zoho Field Map

**Verified 2026-09-15** against the live CRM (`getFields`, `type=used`): 153 Lead fields,
201 Deal fields. Method: case-insensitive regex over both `api_name` and `field_label`.

This exists because the scorecards were written as a **human** checklist. A human auditor
reading a Deal can find "how did you hear about us" in a note or infer it from context. A bot
needs an exact field, and a wrong guess scores every rep 0 on that line silently.

> **Status legend:** ✅ confirmed · ⚠️ confirmed but a trap · ❌ no such field in Zoho

## ❌ Items with no backing field — need a decision

These four cannot be automated as written. Nothing in Zoho matches them.

| Item | Criterion | Finding |
|---|---|---|
| **L18 / D13** | Partner Program | **No field named or labelled anything like "program" exists on Leads or Deals.** Zero matches across all 354 fields in both modules. |
| **D7** | How Did You Hear About Us | Exists on **Leads** (`How_Did_You_Hear_About_Us`) but **not on Deals** — zero matches for "hear" among 201 Deal fields. |
| **D31** | Follow-up scheduled for the client coming back | No "next activity", "follow up", or "next scheduled" field on Deals. |
| **D35** | Admitted Location matches KIPU | No "location" field on Deals. (KIPU half was already deferred to Phase 2; this notes the Zoho half is also absent.) |

**Options for each:** point at the right field if one exists under a name I did not guess ·
create the field in Zoho · or drop the item from the scorecard. Until one is chosen these
score `DEFER` — blank and flagged for the auditor, which is safe but means four items never
get automated.

Note policy OPS-CRM-001 §8 promises reps five business days' notice before a changed checklist
is used to score them, so dropping items is a scheduled change, not an immediate one.

## ⚠️ Traps — same concept, different field per module

| Concept | Leads | Deals |
|---|---|---|
| Insurance Provider | `Private_Insurance_Company` (label "Insurance Provider") | `Insurance_Provider_New` (label "Insurance Provider"). **`Private_Insurance_Company` on Deals is labelled "(DNU)" — Do Not Use.** |
| Insurance Policy Type | `Insurance_Policy_Type` | `Policy_Type` |
| Close Reasoning | n/a | **Two fields, pipeline-dependent:** `Lost_Reasoning` (label "Close Reasoning (Treatment)") and `Close_Reasoning_DUI` |
| Emergency Contact | **Two fields:** `Emergency_Contact_Name` + `Emergency_Contact_Phone_Number` | same two |
| AHCCCS vs commercial provider | `AHCCCS_Insurance_Provider` is separate from the commercial provider field — the right one to check depends on `Insurance_Type` | same |

The Leads/Deals split means a shared `field("Insurance_Provider")` rule would be wrong on one
module or the other. Rules are therefore defined per module, never shared across them.
